# Battle 服务器 (战斗/场景服务)
## 概述
Battle 服务器是分布式游戏服务端架构中的核心服务之一。它主要负责处理对延迟敏感、高频刷新的战斗与场景逻辑。在架构体系中，Gateway 将长连接带来的客户端网络流量进行初步解析，若是与战斗核心行为直接相关（例如移动、施法、技能判定等），或经过 Center 的路由转发后，数据包将流向 Battle 服务器执行具体逻辑。

它致力于满足多形态游戏类型的需求，既能够承载 **MMORPG的大地图AOI**，也具备支持 **竞技游戏(开房间PvP)** 和 **协作游戏(开房副本PvE)** 等独立小场景/战斗房间的管理能力。

## 核心职责

1. **游戏场景与房间管理**
   - 负责游戏场景/关卡的加载、地图数据（如阻挡区域、NavMesh寻路网格等）的解析和维护。
   - 维护各个互相隔离的**战斗房间实例（Rooms）**，实现玩家的加入与离开生命周期控制。对于MMO场景，支持分线地图的管理和动态负载扩容。

2. **核心战斗指令处理**
   - 高频处理来自玩家的输入事件并广播当前状态，确保不同客户端能够及时更新。
   - 处理诸如移动同步（状态同步或帧同步）、碰撞检测、范围判定。

3. **技能及Buff系统判定**
   - 实现复杂的技能效果引擎（比如蓄力攻击、位移技能、AoE范围伤害、控制效果等）。
   - 实施 Buff / Debuff 的时间轴管理及效果演算，提供严谨的伤害结算以避免作弊或逻辑异常。

4. **AOI（区域视野模型）管理 *(针对大场景)* **
   - 维护场景内的实体（Entity），包括所有的玩家、怪物、NPC、交互物件的地标位置。
   - 利用九宫格、十字链表、或四叉树等AOI算法优化广播消息数量：玩家只会看到自己视野范围内实体触发的移动或播放特效。

5. **AI 与怪物逻辑驱动 *(针对PvE / MMORPG)* **
   - 托管系统级怪物/NPC的AI逻辑，执行寻路巡逻、警戒追踪和AI技能施放。
   - 实现刷怪点（Spawner）控制和剧情事件触发条件。

6. **同步与结算上报**
   - 定期持久化玩家或者环境的关键行为快照至 DB / Game 服务器。
   - 在房间战斗结束或副本结算时计算结果（通关耗时、击败怪物数量、玩家伤害统计），并将其发送给 Game 或 Center 服务器，进行奖励派发与战绩登记。

## 工作流示例

* **场景模式（无缝/大场景MMO）**
    1. Center指令玩家从主城传送到某个大地图野外区域，告诉客户端该 Battle 节点的连接端口和授权信息。
    2. 玩家将连接信息发送向 Gateway，网络消息开始导向指定的 Battle 分支。
    3. Battle服将其载入特定野外地图，基于AOI为其广播身边正在打怪的其他玩家。
    4. 玩家在这个节点长期活动，直到他们主动离开地图，或者服务器宕机触发热备节点接管。

* **实例模式（开房间 PvP/PvE）**
    1. 多个玩家通过 Game 向 Center 申请匹配。
    2. 匹配完成后，Center 调度某一台 Battle 服务器分配资源，初始化一个 5v5 （或 4人副本）的新房间。
    3. 各自玩家的客户端被路由至这台 Battle 服务器内部的对应Room。
    4. 产生胜利/失败后结算数据，随后该内存房间被销毁，回收资源。

## 架构扩展性预期
* 独立无状态：尽可能保证战斗结算完即刻可抛毁。不负责常驻数据的写入操作（如充值数据、装备养成等需要经过Game服和DB服）。
* 高性能高吞吐：利用多线程、ECS架构或者Actor模型最大化战斗更新的帧率，维持低GC和CPU压力。
