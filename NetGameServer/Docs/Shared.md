# Shared 项目详细架构与技术文档

## 一、 项目定位
`Shared` 项目是 `Net-Game-Server` 解决方案的底层核心基建。该项目以类库 (Library) 形式存在，绝不包含任何特定的业务逻辑（例如怪物AI或物品结算）。所有的上层服务节点（网关、登陆、游戏服、数据库节点）都默认引入此项目，它提供了统一的数据规范、配置读取标准和工具组件。

## 二、 核心技术栈与依赖
项目基于 `.NET 10` 构建，包含并封装了以下主流高性能组件：
- **Serilog** (`Serilog`, `Serilog.Sinks.Async` 等): 用于构建全局的、异步的、线程安全的日志流水线。
- **Microsoft.Extensions.Configuration** 系: 用于支持标准化的 `appsettings.json` 的配置绑定读取。
- **MemoryPack**: 一款极高效率、零内存分配（Zero Allocation）体验的 C# 专属二进制序列化器。用于对业务数据对象进行超高频的深拷贝及网络序列化。
- **Newtonsoft.Json**: 针对冷数据存储及常规 HTTP API 的配置化解析处理。

## 三、 详细模块拆解

### 1. 核心工具集 (`Shared/`)
这些类充当了全家桶的基础框架：
- **`Log.cs`**: 
  - 包装了 Serilog 的静态方法。支持控制台染色输出、本地滚动文件持久化存储。
  - 通常配置为根据运行环境区分日志输出等级（如 Debug 环境输出更多底层调式信息，Release 环境只输出 Warning 及以上）。
- **`ConfigHelper.cs`**: 
  - 提供单例形式的配置获取能力，封装了读取与热加载 `appsettings.json` 的机制，并能无缝映射为强类型 C# Obejct，避免硬编码。
- **`Json.cs`**: 
  - Json 序列化的轻量级 Helper，通常统一格式化设置如时间戳格式、忽略 Null 字段，并在反序列化异常时抛出受控的业务报错。

### 2. 跨模块模型层 (`Shared/Data/`)
这些实体会被多端同时持有时复用：
- **`User.cs`**: 
  - 描述“玩家”的主干身份。记录了跨所有微服务唯一的账户标识符 (ID/AccountName/Token/角色状态栏位等) 基础数据对象定义。常带有 `[MemoryPackable]` 或类似特性标识，以便全网高效通讯。

### 3. 通信协议定义层 (`Shared/Messages/`)
所有的指令级（RPC或消息体）定义均在此建立契约：
- **`Login/LoginMessages.cs`**: 
  - 用于描述在“登录服 -> 网关 -> 客户端” 三向通讯中具体携带的数据载荷。
  - 例如定义 `C2S_LoginReq` (客户端到服务器的登录请求，含账密)、`S2C_LoginRes` (发还给客户端的结果：包含登录成功令牌或者错误码)。

## 四、 开发规范
1. **轻量与绝对无状态**：不允许在此层存任何运行时的缓存字典或服务器主循环引用对象。
2. **零依赖上层**：任何 Shared 中的代码，不可含有 Network 或 Game 命名空间的引用，防止产生解决方案级循环依赖引用。
