# Gateway 项目详细架构与技术文档

## 一、 项目定位
`Gateway` （网关转发服）节点，是外网唯一可见入口防波堤与调度分配所。该端不会处理任何具体例如吃药回血的等复杂游戏内部功能，而是充当了高速公路“入口匝道引流器”。主要承担负载均衡、外网的通信加密/压缩解析封包、恶意玩家数据风暴清洗防范、并安全反代透传业务连接到后面的微服务或 `Game`/`Login` 容器内。

## 二、 核心技术栈与依赖（推断自 Network 及其职责定位）
如果使用框架中的原生网络，通常结合 ASP.Net 或者底层 TCP/WebSocket 包进行外网暴露：
- 常常会搭配高可用连接和高并发调度功能，底层高度依赖 `Network` 中暴露基于高速 Pipeline （`PipelineTcpServer.cs`）的网络监听，也必然包含对内网 GRPC 会话的支持通道（`Network/Grpc` 或者 `MagicOnion` 相关功能引入）以及基于 HTTP 的代理中间件特性。

## 三、 详细模块拆解

### 1. 会话代理和连通性网桥 (`Managers/GatewaySessionManager.cs`)
- 绝不做业务态检查（除了解析包头长度获取消息种类或者鉴权指令），它主要构建：`外网 Client` -> `网关` ->  `Game 服/或其他内部微服务` 的路由双向穿透隧道。
- **状态维护**: 记录此时有多少外网客户端长连接打在了此网关上。当网关侦测到玩家 Socket `DISCONNECT` 异常断链，需要产生额外的广播，去内网“大喊”通知对应内部服务这个用户掉线让内部进行下放回收，起到集散器作用。

### 2. 节点及网络服务应用配置入口 (`Program.cs`)
- 承载整个程序的生命周期开始。
- 绑定诸如 8180(WS)，或者 5001 (外网高并发 Tcp) 监听。
- 拉取配置文件（`Shared` -> `ConfigHelper`），读取它知道的该大区后的 `Login` 微服务 IP/Port 和多个 `Game` 世界频道的注册表。随后初始化多路由协议代理功能。

## 四、 开发规范
1. **纯正的反向代理思维**: 此项目中不能并且绝不会包含对具体游戏协议中比如金币字段大小变化的校验相关验证和读取。它的定位只拆包（或读头），转发包。
2. **极端内存和流量性能控制**: 不允许有任何可能引发长时间堵塞的操作停滞网关，因为此层一旦卡顿，该区内几百几千名在线全部会出现明显的网络超时感。
