# DB 数据服务

`DB` 服务用于统一封装数据访问能力，对业务层屏蔽底层数据库/缓存细节，承担持久化、查询和一致性保障职责。

## 核心职责
- **数据读写代理**：处理账号、角色、好友、聊天、统计等业务数据的存取。
- **全局 ID 协作**：为依赖递增序列的业务提供统一来源（如 UID 初始化协作）。
- **连接与资源管理**：维护数据库连接池、缓存连接、重试与超时控制。

## 通信协议
业务服务与 `DB` 的请求/响应统一采用：
- `[MsgId(4)][RequestId(8)][Payload]`

说明：
- `RequestId` 用于请求响应匹配；无需匹配时可为 `0`。
- 禁止在 DB 链路中使用 `[MsgId][Payload]` 的简化格式。

## 设计建议
- 业务层只面向消息协议，不直接拼接底层 SQL/缓存细节。
- 数据热点建议配合缓存与批量策略，减少高峰期 IO 抖动。
- 对关键写操作增加幂等与失败补偿机制。
